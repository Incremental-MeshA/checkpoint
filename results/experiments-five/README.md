# Пять планировщиков из experiments на car16

**Stamp — первый выбор для навигации на проверенных задачах.** Среднее полное время эпизода составило 186,0 мс против 297,1 мс у штатного mesh MPGAA* и 407,1 мс у mesh A*. Это ускорение в 1,60 и 2,19 раза соответственно. Stamp достиг цели в 79 из 81 эпизода. Ближайший по полному времени кандидат Boundary достиг тех же 79 целей за 187,3 мс в среднем. Разница между ними меньше 1%.

**MD-A* Scan интереснее для редких правок при уже найденном пути.** На одинаковых траекториях MPGAA* при 0,1% изменений MD-A* Scan тратил на повторные запросы 0,11 мс за эпизод против 3,12 мс у MPGAA*. Первый поиск занимал около 71 мс, поэтому в полном навигационном эпизоде выигрыш при 0,1% составил лишь 1,8%.

## Отбор и перенос

Критериями были применимость к направленным примитивам car16, поддержка одновременных блокировок и освобождений и возможность проверить выигрыш относительно местного MPGAA*. В выборку вошли три исследовательские ветки. Четыре кандидата принадлежат семейству MPGAA*, что позволяет сравнить способы проверки проходимости при общей процедуре обучения.

| Вариант в стенде | Что перенесено и зачем проверять |
|---|---|
| `md_scan` | Вариант MD-A* с просмотром отложенных освобождений. Отдельная рабочая карта и оценка длины пути через изменённую клетку позволяют вернуть суффикс старого маршрута. Внутренний поиск выполняет местный mesh MPGAA*. Проверяем, окупается ли сертификат при редких изменениях. [Исходная реализация MD Scan](https://github.com/Incremental-MeshA/experiments/blob/691b8f010966a1089afe422a5c130e46f70e1204/cpp/include/ima/deferred.hpp) |
| `mpgaa_boundary` | Поиск раскрывает позы на границах примитивов. При обходе общего префикса один раз проверяет клетку для нескольких манёвров и сохраняет маску проходимости. После правок сразу удаляет потенциально устаревшие маски. Так измеряем эффект перехода к поиску по полным позам. [Boundary](https://github.com/Incremental-MeshA/experiments/blob/3b63d6bd55c7f563d784e2290047e514cbbb2584/cpp/mpgaa_mesh/algorithms.hpp) |
| `mpgaa_stamp` | Тайлы 8×8 хранят версию последней правки. Планировщик проверяет актуальность маски при обращении к позе. Это позволяет отложить работу для поз, к которым робот больше не вернётся. [Stamp](https://github.com/Incremental-MeshA/experiments/blob/7b8876cdfd798c0ee3768f701379e2dff33b416b/cpp/mpgaa_lazy/algorithms.hpp) |
| `mpgaa_batch` | К Stamp добавлен выбор способа восстановления эвристики. Для пакета освобождений планировщик сравнивает оценку числа проверок от клеток с числом исходящих дуг у поз с повышенной эвристикой и выбирает пространственный индекс или просмотр этих дуг. [Batch](https://github.com/Incremental-MeshA/experiments/blob/7b8876cdfd798c0ee3768f701379e2dff33b416b/cpp/mpgaa_lazy/algorithms.hpp) |
| `mpgaa_witness` | Расширяет Batch. При обновлении маски повторно проверяет ранее найденные препятствия. Если они по-прежнему перекрывают все продолжения ветви, её можно пропустить. Проверяем, окупается ли хранение препятствий на картах со стенами. [Witness](https://github.com/Incremental-MeshA/experiments/blob/7b8876cdfd798c0ee3768f701379e2dff33b416b/cpp/mpgaa_lazy/algorithms.hpp) |

При отборе также рассмотрены алгоритмы для полного mesh-графа. В исходном исследовании Cascade ускорял восстановление относительно обычного Mesh-MPGAA, но уступал ему по полному эпизоду в основной car16-серии. Fast Lift улучшил собственную предыдущую реализацию. У Envelope основной механизм срабатывает при повторных отрицательных ответах, а навигационный сценарий этого проекта завершает эпизод при первом `no_path`. Эти наблюдения определили выбор гипотез для переноса. Все времена ниже измерены локально. [Cascade](https://github.com/Incremental-MeshA/experiments/blob/49b1df9ee952f36cbc240c0a3be713feef690a1b/docs/mesh_vertex/report.md) · [Fast Lift](https://github.com/Incremental-MeshA/experiments/blob/f433b9e3e6bba1ff398a2a3f23bf991cc54886a2/docs/mesh_lift_fast/report.md) · [Envelope](https://github.com/Incremental-MeshA/experiments/blob/de6c4e93f2ce76500c418fc9fbbdb5026b4c3ff9/docs/mesh_envelope/report.md)

Все адаптации используют исходные ID, следы и стоимости 384 примитивов проекта. Четыре варианта с масками строят дерево общих префиксов по этим следам. Поиск и восстановление эвристики используют местную арифметику `Cost` и индексированную очередь. Для Boundary перенос консервативно удаляет маску при правке тайла, пересекающего прямоугольник следов. Для Batch оценка учитывает все освобождения пакета. Оба решения могут дать дополнительную работу по сравнению с более точным отбором в исходной ветке. [Маски](../../algorithms/mpgaa/motion_masks.hpp) · [Поиск и восстановление](../../algorithms/mpgaa/mpgaa.cpp)

В MD Scan для нижней оценки использовано целочисленное расстояние Чебышёва. Из суммы расстояний от старта до открывшейся клетки и от неё до цели вычитается поправка на изгиб примитива. Её величина покрывает максимальное превышение суммы этих двух плеч внутри любого следа над округлённой вниз длиной примитива. Благодаря этому клетка внутри дуги может открыть более дешёвый путь даже при большом удалении от её концов. [Реализация сертификата](../../algorithms/md_scan/md_scan.cpp)

## Навигация

Профиль `quick`, три задачи на каждой из карт Labyrinth, Moscow_0_512 и 32room_000. Для каждой задачи использованы три seed мира. Семь планировщиков запускались последовательно, в фиксированном порядке в каждой паре «задача, seed». По каждой серии и каждому планировщику получено 27 эпизодов. Лимиты составляли 60 с на эпизод и 1 800 с на серию. Все 567 эпизодов завершились, из них 549 достижением цели и 18 ответом об отсутствии пути на известной карте. Всего выполнено 4 926 запросов.

В таблице каждая ячейка содержит **среднее полное время / среднюю сумму времён перепланирования за эпизод**, в миллисекундах. Полное время включает инициализацию, первый поиск, перепланирования и симуляцию. При полной видимости пакет изменений приходит каждые 10 исполненных примитивов. При радиусе 25 наблюдение проводится после каждого примитива, а перепланирование запускают новые сведения. В последнем столбце указан средний первый запрос по всем 81 эпизоду.

| Планировщик | Полная, 0,1% | Полная, 1% | Радиус 25 | Первый запрос, мс | Цель, из 81 |
|---|---:|---:|---:|---:|---:|
| Mesh A* | 443,91 / 8,67 | 423,59 / **9,02** | 353,91 / 231,39 | 36,61 | 77 |
| Mesh MPGAA* | 339,36 / 1,93 | 383,21 / 13,88 | 168,72 / 25,09 | 69,02 | 78 |
| MD-A* Scan | 333,25 / **0,20** | 378,52 / 12,24 | 168,15 / 24,54 | 68,34 | 78 |
| Boundary | **210,40** / 2,26 | 242,04 / 11,57 | 109,40 / 15,84 | **30,72** | **79** |
| Stamp | 212,66 / 1,64 | **239,67** / 10,53 | **105,55** / 12,06 | 30,92 | **79** |
| Batch | 216,60 / 4,49 | 257,17 / 26,62 | 105,94 / **12,01** | 31,09 | **79** |
| Witness | 217,18 / 4,63 | 260,42 / 27,77 | 108,03 / 12,55 | 32,45 | **79** |

При 0,1% все варианты достигли 27 целей. При 1% A* достиг 25, MPGAA* и MD Scan — по 26, остальные — по 27. При радиусе 25 каждый вариант достиг 25 целей. Разные оптимальные маршруты могут иметь разное число примитивов, что меняет и позу при следующем обновлении. Например, за серию с радиусом 25 у Stamp был 471 повторный запрос, у MPGAA* — 619, у A* — 662. По полному времени Stamp опередил MPGAA* на каждой карте в каждом режиме. При радиусе 25 средние времена Stamp и MPGAA* составили 158 и 203 мс на Labyrinth, 83 и 177 мс на Moscow, 76 и 126 мс на 32room.

## Одинаковые позы и изменения для всех семи алгоритмов

Для первого seed каждой задачи из журналов штатного MPGAA* взяты точные позы, цели и пакеты правок. Каждый алгоритм получил их в исходном порядке в новом процессе на эпизод. Проверено 27 последовательностей с 271 запросом (25, 25 и 221 по сериям). Из 1 897 ответов все совпали по достижимости и стоимости с журналом MPGAA* при абсолютном допуске 10⁻⁶. Максимальная разность стоимостей составила 7,11 × 10⁻¹⁵. В сравнение входит и авторский mesh A*, который запускает новый поиск на каждом запросе. [Строки сравнения и времена](fixed-requests.csv)

| Планировщик | Перепланирование при 0,1%, мс | При 1%, мс | При радиусе 25, мс |
|---|---:|---:|---:|
| Mesh A* | 8,08 | **8,95** | 187,11 |
| Mesh MPGAA* | 3,12 | 12,94 | 31,24 |
| MD-A* Scan | **0,11** | 11,72 | 32,17 |
| Boundary | 4,83 | 15,45 | 25,90 |
| Stamp | 3,91 | 14,32 | **22,02** |
| Batch | 7,77 | 36,20 | **22,02** |
| Witness | 7,97 | 40,47 | 23,03 |

Здесь также приведена средняя сумма повторных запросов на эпизод. При радиусе 25 преимущество Stamp перед MPGAA* сохранилось на одной траектории — 1,42×. При 1% изменений быстрее всех перепланировал повторный A*, а у Stamp выигрыш полного эпизода связан с первым поиском и ходом навигации. Переход от Stamp к Batch увеличил время на тех же запросах с 14,32 до 36,20 мс. Сохранение препятствий в Witness добавило ещё 4,28 мс. На этих трёх сериях дополнительные механизмы Batch и Witness не дали устойчивого выигрыша относительно Stamp. Разницу в сотые доли миллисекунды между Stamp и Batch при радиусе 25 следует считать ничьей. Выводы ограничены девятью задачами, одной машиной и указанными режимами. Три seed меняют среду, фиксированная проверка использует один из них.

## Воспроизведение

Замеры выполнены на Windows 10 x64, Intel Core i5-9400F, GCC 15.2.0, C++17 Release `-O3 -DNDEBUG`, Python 3.14.5rc1. Исходная ревизия местного проекта — `4a9b4e32`. SHA-256 измеренного исполняемого файла — `bc9b03f44b2c098d3040caa9cb1a08551401f91bcdb76dcb7272e5a024a5c5f3`. Архив содержит три каталога, каждый со своим `run.json`, `summary.csv` и журналом каждого эпизода. Манифесты содержат списки задач, seed и хеши входов. Длительности серий составили 65,5, 73,0 и 43,9 с.

Команды выполняются из корня проекта. Для новых замеров укажите новый каталог вывода. Для проверки сохранённых замеров распакуйте `journals.zip` в `runs/five` и переходите сразу к `compare`, `replay` или `fixed_requests`.

```shell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
python -m bench run --suite experiments --change-percent 0.1 --repeats 3 --budget-seconds 1800 --output runs/five/navigation-0.1
python -m bench run --suite experiments --change-percent 1 --repeats 3 --budget-seconds 1800 --output runs/five/navigation-1
python -m bench run --suite experiments --config config/visibility.json --radius 25 --repeats 3 --budget-seconds 1800 --output runs/five/visibility-25
python -m bench compare runs/five/navigation-1
python -m bench replay runs/five/visibility-25 --regenerate
python -m bench.fixed_requests runs/five/navigation-0.1 runs/five/navigation-1 runs/five/visibility-25
```

В малых задачах варианты проверены независимой Дейкстрой, включая восстановление после освобождения клетки внутри изогнутого примитива. Для 15 журналов (каждый кандидат в каждой серии) воспроизведение с генерацией правок из seed подтвердило маршруты, исходы и счётчики. Прошли 23 из 24 тестов Python и все 4 теста JavaScript. Единственная ошибка Python относится к отсутствующему в текущей ветке архиву `results/full-pinned`. Все 57 хешей этого архива отдельно сверены по исторической ревизии `fb854b83`.
