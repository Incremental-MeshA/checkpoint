# Результат эксперимента MPGAA*

[Графики и таблицы](timing.html) · [Средние и счётчики](means.csv) · [Исходы](outcomes.csv) · [Эпизоды](episodes.csv) · [Параметры сборки и серий](series.json)

Проверены 12 карт, 36 задач, девять настроек и три повтора в профиле `long`. Сборка Release из коммита `b045998`. В пяти вариантах выполнены 2 340 эпизодов. В 2 022 достигнута цель, в 302 получен ответ `no_path`, 16 остановлены через 60 секунд. Времена сравниваются на 464 общих комбинациях задачи, настройки и повтора. Отношение средних суммарных времён перепланирования вычислено отдельно для каждой настройки.

| Настройка | Локальный ремонт | Сжатие | Оба изменения |
|---|---:|---:|---:|
| Изменения 0,1% | 1,13× | 1,51× | 1,59× |
| Изменения 0,5% | 1,12× | 1,59× | 1,59× |
| Изменения 1% | 1,13× | 1,55× | 1,59× |
| Изменения 5% | 1,09× | 1,66× | 1,68× |
| Изменения 10% | 1,09× | 1,60× | 1,61× |
| Радиус 25 | 1,03× | 1,91× | 1,97× |
| Радиус 50 | 0,97× | 1,67× | 1,77× |
| Радиус 100 | 1,14× | 1,54× | 1,60× |
| Радиус 200 | 1,11× | 1,57× | 1,62× |

Базовая линия равна времени исходного MPGAA* на mesh. Наибольший вклад дало сжатие. Для совместного варианта полное время эпизода сократилось в 1,57–2,00 раза. На всех девяти настройках lattice-MPGAA* остался быстрее совместного варианта по перепланированию в 2,46–4,84 раза. Число извлечений из очереди ремонта при одном локальном ремонте составило 33–39% от исходного. Время и счётчики относятся к этой машине и выборке; порядок пяти вариантов был фиксирован.

При навигации каждый планировщик выбирает свой путь. В журналах стоимость и достижимость совпали для всех 7 406 запросов, общих хотя бы для двух вариантов (одинаковые задача, повтор, поза и история правок). Дополнительно для каждой пары карты и настройки взята первая в манифесте завершённая траектория исходного mesh с перепланированием при повторе 0. Все пять вариантов воспроизвели 885 запросов на 52 таких траекториях, без расхождений по стоимости или достижимости. [Сверка журналов](checks.csv) · [Фиксированные запросы](fixed-replay.csv)

Журналы эпизодов и зафиксированный бинарник этого прогона находятся в `runs/prefix-full` рабочего каталога. Путь к журналу в `episodes.csv` отсчитывается от каталога CSV. Для контрольного воспроизведения используется команда `python -m bench.prefix_replay runs/prefix-full results/prefix/fixed-replay.csv` с переменной `MESH_PLANNER`, указывающей на бинарник из `runs/prefix-full/binary`.
